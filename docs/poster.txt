  The Knot Invariant Calculator

  A C++ application that computes the Jones polynomial of mathematical knots using the Kauffman bracket algorithm.

  Knots are closed curves in 3D space. The Jones polynomial is a topological invariant that distinguishes knot types, with applications in molecular biology, quantum physics, and polymer science. The Kauffman bracket has O(2ⁿ) complexity for n crossings — a 21-crossing knot
  needs 4.2 million recursive calls.

  Input: Dowker–Thistlethwaite (DT) notation, integer sequences from databases like KnotInfo. Output: Jones polynomial V_K(A), verified against published tables.

  Cache key: record which smoothings have been applied, e.g. DiagramState{0->A, 1->B, 2->A}.

  Crossings are always processed in ascending order (0, 1, 2, ...), which creates a perfect binary tree where every root-to-leaf path is unique. No two branches ever reach the same state.

  ---
  Key Algorithm Features

  The Kauffman Bracket Expansion

  Each crossing is smoothed in two ways, creating a recursive binary tree:

  ⟨K⟩ = A · ⟨A-smooth⟩ + A⁻¹ · ⟨B-smooth⟩

  Base case: when all crossings are smoothed, count resulting circles k:

  ⟨k circles⟩ = (−A² − A⁻²)^(k−1)

  Jones Polynomial

  Normalise the bracket by the writhe w:

  V_K(A) = (−A)^(−3w) · ⟨K⟩

  Arc Endpoint Model

  A knot with n crossings has 2n arc segments. Smoothing reconnects endpoints according to crossing orientation. Union-Find with path compression tracks connected components in O(α(n)) amortised time.

  Implementation

  Language and containers: C++17 throughout. std::map<int,int> stores sparse Laurent polynomials (power to coefficient); zero-coefficient terms are erased after each addition.

  Input parsing: each DT notation integer maps to one crossing. Its sign encodes orientation (+1 or −1); its absolute value gives the paired arc position in the range [0, 2n).

  Timing: std::chrono::high_resolution_clock measures bracket computation alone, separately from Jones normalisation. Cached and uncached runs each use a fresh KauffmanBracket instance so neither warms the other's state.

  Build: g++ -std=c++17 -O2 via Makefile. Git history tracks the path from an early heuristic component-counting prototype to the topology-based cache.

  ---
  Solution: Topology-Based Caching

  The key idea

  Stop recording what smoothings were applied; record what they produced.

  Two different A/B choice sequences can yield the same arc connectivity with the same crossings remaining. When that happens, both branches produce identical results — the second one can reuse the first's cached subtree.

  Example (7 crossings):

  Branch A: 0->A, 1->A, 2->B, 3->A => connectivity X, crossings {4,5,6} remain
  Branch B: 0->B, 1->B, 2->A, 3->A => connectivity X, crossings {4,5,6} remain

  Cache hit. Branch B reuses Branch A's result.

  Cache Key Structure

  struct CacheKey {
      vector<int> connectivity; // canonical arc IDs
      int remaining;            // bitmask: bit i = crossing i unsmoothed

      bool operator<(const CacheKey& other) const {
          if (remaining != other.remaining)
              return remaining < other.remaining;
          return connectivity < other.connectivity;
      }
  };

  map<CacheKey, Polynomial> cache;

  The remaining bitmask clears bit i via remaining & ~(1 << i). Safe limit: 30 crossings with a 32-bit signed int (bit 31 shift is undefined behaviour in C++).

  Canonical Connectivity

  The Equivalence Problem

  Two Union-Find states may be structurally identical but represented differently depending on construction order. Raw roots [7,7,2,2] and [3,3,0,0] encode the same pattern — a canonical form is needed for cache keys to compare equal.

  Canonicalization Algorithm

  vector<int> canonicalize(vector<int> uf, int n) {
      vector<int> canonical(2 * n);
      map<int,int> id_map;
      int next_id = 0;

      for (int i = 0; i < 2 * n; i++) {
          int root = uf_find(uf, i);
          if (id_map.find(root) == id_map.end())
              id_map[root] = next_id++;
          canonical[i] = id_map[root];
      }
      return canonical; // components numbered 0, 1, 2, ...
  }

  Endpoints scanned left-to-right, assigning IDs in order of first appearance. Two equivalent topologies always produce identical keys regardless of construction order.

  Complexity: O(2n · log k), k = distinct components (typically k < 5).

  Smoothing Operations

  At each crossing, two arc endpoints arrive and two depart. A-smoothing and B-smoothing reconnect them in one of two patterns, determined by crossing sign:

  void apply_smoothing(vector<int>& uf,
          const pair<int,int>& pos, int sign, char type, int n) {
      auto [p, q] = pos;
      int before_p = (p - 1 + 2*n) % (2*n);
      int before_q = (q - 1 + 2*n) % (2*n);
      bool cross_connect = (type == 'A') == (sign > 0);
      if (cross_connect) {
          uf_unite(uf, before_p, q);
          uf_unite(uf, before_q, p);
      } else {
          uf_unite(uf, before_p, before_q);
          uf_unite(uf, p, q);
      }
  }

  Cross-connect (A-smooth of positive crossing): joins the strand arriving at p to the one leaving at q, and vice versa. Parallel-connect (B-smooth of positive crossing): joins both arrivals together and both departures together, potentially merging or splitting components.

  ---
  Analysis: When Memoization Helps

  Torus knots have very regular structure — intermediate states rarely coincide, which is why hit rates top out around 24%.

  The cache would pay off for:
  - Pretzel and composite knots: more coincidental states, likely 40–50%+ hit rates
  - std::unordered_map with custom hash: O(1) average vs O(log n) lookup
  - Lazy canonicalization: compute only on store, not on every lookup check

  Design Decisions and Future Work

  Sparse polynomial storage: std::map<int,int> stores only non-zero terms. T(2,15)'s bracket spans A⁻¹⁹ to A¹⁷ in steps of 4 — 10 terms.

  Value-based recursion: Union-Find passed by value so each branch gets an independent copy. Works fine for n < 25.

  Future work:
  - Profile with Valgrind/gprof to find where the overhead actually lives
  - Test on pretzel and composite knots for higher hit rates
  - Implement unordered_map with custom hash
  - Port to Raspberry Pi for embedded deployment comparison
